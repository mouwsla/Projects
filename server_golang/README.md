
# Map Tile Microserver

Микросервер растровых карт, разработанный на **Go**. Предназначен для хранения и выдачи картографических тайлов в формате PNG через HTTP API.

В качестве хранилища используются базы данных **SQLite в формате MBTiles**. Сервер поддерживает параллельную обработку запросов, кэширование на стороне клиента и корректное завершение работы.

## Возможности

- Выдача растровых PNG-тайлов через HTTP.
- Поддержка масштабов от 0 до 12.
- Работа с несколькими базами MBTiles.
- Преобразование координат XYZ в TMS.
- Получение метаданных карт в формате JSON.
- Проверка доступности сервера.
- Параллельная обработка HTTP-запросов.
- Обработка ошибок и проверка координат.
- Настраиваемые таймауты HTTP-сервера.
- Graceful Shutdown (SIGINT, SIGTERM).
- Запуск через Docker Compose.
- Автоматические тесты и бенчмарки.

## Технологии

- **Go** — основной язык разработки.
- **net/http** — HTTP-сервер и маршрутизация.
- **database/sql** — работа с базами данных.
- **modernc.org/sqlite** — SQLite-драйвер без CGO.
- **MBTiles** — хранение растровых карт.
- **Docker / Docker Compose** — контейнеризация.
- **testing / httptest** — тестирование HTTP API.
- **pprof** — профилирование производительности.

## Картографические данные

Сервер использует две базы MBTiles:

| База данных | Используемые масштабы |
|---|---|
| russia_raster_z0_z6.mbtiles | 0–6 |
| russia_raster_z5_z12.mbtiles | 7–12 |

Формат тайлов — PNG.

Базы открываются в режиме **только для чтения**.

Пути к базам можно настроить через переменные окружения:

```bash
MBTILES_LOW_PATH=maps/russia_raster_z0_z6.mbtiles
MBTILES_HIGH_PATH=maps/russia_raster_z5_z12.mbtiles
```

Если переменные не заданы, используются стандартные пути из таблицы выше.

**Важно:** файлы MBTiles не распространяются вместе с исходным кодом. Для запуска необходимо самостоятельно подготовить соответствующие базы и разместить их в каталоге `maps/`.

## Запуск

### Через Docker Compose

Требуется установленный Docker с поддержкой Compose.

1. Клонировать репозиторий

2. Создать каталог `maps/` и разместить в нём файлы MBTiles.

3. Убедиться, что в `compose.yaml` настроено подключение каталога с картами.

4. Собрать и запустить контейнер:

```bash
docker compose up -d --build
```

Проверить состояние:

```bash
docker compose ps
```

Просмотреть логи:

```bash
docker compose logs -f
```

Остановить сервер:

```bash
docker compose stop
```

### Без Docker

Требуется **Go 1.22 или новее**.

Установить зависимости:

```bash
go mod download
```

Запустить сервер:

```bash
go run .
```

По умолчанию сервер слушает порт `8080`.

## HTTP API

### GET /health

Проверка доступности сервера.

Пример запроса:

```bash
curl http://localhost:8080/health
```

Ответ:

```text
OK
```

HTTP-статус: `200 OK`.

### GET /metadata

Получение метаданных подключённых MBTiles-баз.

Пример:

```bash
curl http://localhost:8080/metadata
```

Пример структуры ответа:

```json
{
    "lowDataBase": {
        "name": "Russia raster z0-z6 gray",
        "format": "png",
        "minzoom": "0",
        "maxzoom": "6"
    },
    "highDataBase": {
        "name": "Russia raster z5-z12",
        "format": "png",
        "minzoom": "5",
        "maxzoom": "12"
    }
}
```

Фактический набор полей зависит от содержимого таблицы `metadata` в каждой базе.

Метаданные считываются при запуске сервера.

### GET /tiles/{z}/{x}/{y}.png

Получение растрового картографического тайла.

Параметры:

- `z` — уровень масштабирования (0–12).
- `x` — горизонтальная координата.
- `y` — вертикальная координата в системе XYZ.

Пример:

```bash
curl http://localhost:8080/tiles/3/2/2.png \
  --output tile.png
```

При успешном запросе сервер возвращает PNG-изображение.

Заголовки ответа:

```http
Content-Type: image/png
Cache-Control: public, max-age=86400
```

Кэширование на стороне клиента разрешено на 24 часа.

### Преобразование XYZ в TMS

HTTP API принимает координаты XYZ, но MBTiles использует координаты TMS.

Преобразование вертикальной координаты:

```text
tmsY = (2^z - 1) - y
```

После преобразования тайл извлекается из SQLite.

### HTTP-статусы

| Код | Описание |
|---|---|
| 200 | Запрос успешно обработан |
| 400 | Неверные координаты или формат тайла |
| 404 | Тайл не найден или масштаб не поддерживается |
| 500 | Ошибка чтения данных из SQLite |

## Настройки сервера

HTTP-сервер использует следующие параметры:

| Параметр | Значение |
|---|---|
| Порт | 8080 |
| ReadHeaderTimeout | 5 секунд |
| WriteTimeout | 15 секунд |
| IdleTimeout | 60 секунд |
| Shutdown Timeout | 8 секунд |

При получении SIGINT или SIGTERM сервер прекращает принимать новые соединения и ожидает завершения активных HTTP-запросов.

После остановки HTTP-сервера закрываются подключения к SQLite.

## Тестирование

Проект содержит автоматические тесты HTTP API и SQLite.

Запуск всех обычных тестов:

```bash
go test -v ./...
```

Проверка на гонки данных:

```bash
go test -race ./...
```

Основные проверки:

- Доступность `/health`.
- Корректность JSON в `/metadata`.
- Чтение метаданных из SQLite.
- Проверка допустимых координат.
- Обработка неподдерживаемых масштабов.
- Получение PNG из обеих баз.
- Обработка отсутствующих тайлов.
- Обработка ошибок базы данных.

Для функциональных тестов используются временные SQLite-базы.

## Нагрузочное тестирование

В проекте предусмотрены бенчмарки для измерения производительности.

Тестирование HTTP-обработчиков:

```bash
go test -run '^$' \
  -bench '^BenchmarkTiles$' \
  -benchmem \
  -benchtime=2s
```

Тестирование через локальный HTTP:

```bash
go test -run '^$' \
  -bench '^BenchmarkHTTP$' \
  -benchmem \
  -benchtime=2s \
  -cpu=1,4,8
```

Бенчмарки выполняются с использованием картографических баз MBTiles.

Измеряются:

- Время обработки запроса (`ns/op`).
- Пропускная способность.
- Выделение памяти (`B/op`).
- Количество аллокаций (`allocs/op`).
- Производительность параллельных запросов.

## Профилирование

Для анализа производительности используется `pprof`.

Создание CPU- и memory-профилей:

```bash
go test -run '^$' \
  -bench '^BenchmarkHTTP/High_z7/Mixed/Parallel$' \
  -benchtime=3s \
  -cpu=4 \
  -cpuprofile=cpu.prof \
  -memprofile=mem.prof
```

Анализ CPU:

```bash
go tool pprof -top cpu.prof
```

Анализ выделения памяти:

```bash
go tool pprof -top -alloc_space mem.prof
```

Результаты профилирования не включаются в Git-репозиторий.

## Работа по локальной сети

Сервер может принимать HTTP-запросы от других устройств в доступной сети.

Для проверки подключения:

```bash
curl http://<IP_СЕРВЕРА>:8080/health
```

Пример получения тайла:

```text
http://<IP_СЕРВЕРА>:8080/tiles/7/3/4.png
```

Необходимо обеспечить сетевую доступность порта `8080`.

Текущая реализация использует обычный HTTP без встроенной аутентификации. Рекомендуется запускать сервер в доверенной локальной сети или ограничивать доступ сетевыми правилами.

## Примечания

- Сервер предназначен для выдачи готовых растровых тайлов.
- Генерация и рендеринг карт не выполняются.
- Для работы необходимы заранее подготовленные MBTiles-базы.
- Исходные картографические данные хранятся отдельно от кода проекта.
- Производительность зависит от оборудования, размера тайлов, SQLite и характеристик сети.

## Лицензия

Лицензия на исходный код пока не указана.

Условия использования картографических данных определяются отдельно их источниками и лицензиями.
