# Astrophysics Simulator v0.8.0

Интерактивный учебно-исследовательский симулятор на **C++20, Qt 6 и OpenGL** с четырьмя режимами: Milky Way, Black Hole, Galactic Center и Physics. Проект работает на macOS (Intel и Apple Silicon), Windows и Linux; внешние астрономические наборы данных для первого запуска не нужны.

> Статус: **учебно-исследовательский прототип**, не полноценный пакет GRMHD или реконструкция реального Млечного Пути. Математическое ядро и GLSL-шейдеры проходят автоматическую проверку; Qt GUI собран с AppleClang/Qt 6 на macOS.

## Системные требования

- C++20 компилятор: Xcode Command Line Tools (macOS) / GCC или Clang / MSVC.
- CMake 3.20+, Qt **6.4+** с компонентами Widgets, OpenGL, OpenGLWidgets.
- Видеоускоритель с поддержкой OpenGL 4.1 Core на macOS или OpenGL 3.3 Core на других ОС.
- ОЗУ от 4 ГБ, для 1 млн звёзд лучше 8–16 ГБ.

## Быстрый старт

### macOS

```bash
xcode-select --install  # если инструменты разработчика ещё не установлены
brew install cmake qt
git clone <URL-репозитория>
cd AstrophysicsSimulator
./build_macos.sh
```

Скрипт находит Homebrew Qt, собирает Release-конфигурацию, запускает тесты и открывает приложение. Для последующих запусков можно дважды щёлкнуть `run_macos.command`.

### Ручная сборка на macOS

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH="$(brew --prefix qt)" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
open build/AstrophysicsSimulator.app
```

**Если Qt находится в нестандартном каталоге:** передай путь Qt через `-DCMAKE_PREFIX_PATH=/путь/к/qt`.

## Windows / Linux

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH="/путь/к/Qt/6.x/компилятор"
cmake --build build --config Release -j 4
```

На Linux Qt6 можно установить системным пакетным менеджером. Запуск: `./build/AstrophysicsSimulator`.

## Четыре режима

**1. Milky Way:** 100 000 звёзд по умолчанию, до 1 млн по выбору. Положения и скорости генерируются синтетически. Интегрируются орбиты звёзд в статическом осесимметричном потенциале: диск Миямото—Нагаи, балдж Эрнквиста, логарифмическое тёмное гало и центральная точечная масса с численным смягчением. Интегратор velocity-Verlet (Leapfrog). Звёзды не притягивают друг друга напрямую (это **не** N-body и не полноценная модель эволюции всей галактики). Спиральная структура — начальные условия; без плотностных волн со временем она сдвигается.

**2. Black Hole:** единая интерактивная сцена по архитектуре из указанного видеоролика. Чёрная дыра, диаграмма искривлённого пространства, световые лучи и аккреционный диск находятся в одной системе координат и используют одну камеру. Сетка строится по точной диаграмме вложения Фламма `z/Rs = 2 sqrt(r/Rs - 1)`. Семь лучей распространяются по точному уравнению экваториальной нулевой геодезической Шварцшильда `u''+u=3u²/2` и интегрируются RK4: бело-голубые лучи отклоняются и уходят, оранжевые пересекают горизонт и захватываются. Горизонт реально перекрывает захваченные траектории при композиции кадра.

Поверх той же сцены отображается вращающаяся чёрная дыра Керра (`-0.998 ≤ a* ≤ 0.998`). Горизонт и экваториальный ISCO вычисляются аналитически, граница тени строится из констант движения сферических нулевых геодезических Керра (`ξ`, `η`). Для диска учитываются ISCO, приближённый гравитационный/доплеровский сдвиг, усиление `g³` и первый высший образ дальней стороны. Анимированное закручивание координатных линий показывает направление frame dragging.

Визуальная воронка остаётся диаграммой пространственного среза, а не буквальной формой 4D пространства-времени. Лучи, в отличие от воронки, являются непосредственно интегрированными геодезическими.

**3. Galactic Center:** связанная барицентрическая система из подвижной чёрной дыры и 15 массивных объектов. RK4 интегрирует взаимное ньютоновское N-body-притяжение, 1PN-поправку Шварцшильда и 1.5PN спин-орбитальный эффект Лензе—Тирринга; шаг адаптируется к локальному динамическому времени. Чёрная дыра получает обратную реакцию и физически малое рефлекторное движение. При пересечении радиуса потерь объект либо приливно разрушается (`r_t = R*(M/m)^(1/3)`), либо напрямую захватывается внутри зависящего от спина радиуса предельно связанной орбиты. Масса, скорость, импульс и проекция углового момента поглощённого вещества обновляют чёрную дыру. В сцену добавлен `TDE probe`, который демонстрирует разрушение примерно через 0.8 года модельного времени. Белые/синие линии остаются ньютоновскими опорными эллипсами.

**4. Physics:** встроенная адаптация сцены [`kavan010/black_hole`](https://github.com/kavan010/black_hole). Внешняя композиция и управление сохранены: чёрный фон, полупрозрачная серая квадратная сетка `25×25`, низкоразрешённый Schwarzschild ray tracer `200×150`, чёрная область горизонта, оранжевый диск от `2.2 Rs` до `5.2 Rs`, жёлтый и красный сферические объекты. Камера начинает на расстоянии около `5 Rs`, имеет FOV `60°`, вращается ЛКМ/СКМ и масштабируется колесом в тех же пределах.

Сцена работает в единицах `Rs=1`, `c=1`. Два объекта соответствуют исходным солнечным массам на расстоянии около `31.52 Rs`; гравитация изначально выключена. `G` переключает её, удержание ПКМ временно включает, отпускание выключает — как в референсе. При включении объекты движутся в центральном поле и взаимно притягиваются; интегратор заменён на устойчивый velocity-Verlet. Захват горизонтом и восстановление объекта на исходной позиции оставлены как расширение нашего симулятора.

Оригинальный OpenGL 4.3 compute shader недоступен на macOS. Поэтому та же экранная схема трассировки перенесена в низкоразрешённый GLSL 330 fragment pass, после чего результат линейно масштабируется и альфа-компонуется поверх сетки. Исходный код и бинарные ресурсы референса не включены.

Кнопка `ФОТОННЫЕ ТРАЕКТОРИИ` накладывает модель гравитационного рассеяния света непосредственно на основную сцену Physics, не заменяя чёрную дыру, диск и геометрическую сетку. Девять изначально параллельных лучей интегрируются в плоскости Шварцшильда: внешние лучи отклоняются и уходят, околокритические оборачиваются вокруг фотонной сферы, а два внутренних пересекают горизонт. Движущиеся маркеры показывают направление распространения. На диаграмме отдельно отмечены горизонт `r=Rs`, фотонная сфера `r=1.5 Rs` и критический impact parameter `b=3√3 Rs/2`.

Кнопка `ВО ВЕСЬ ЭКРАН` доступна во всех четырёх режимах. Она скрывает боковую панель, но не меняет выбранную модель; `Esc` восстанавливает прежний размер окна и интерфейс. На Retina/HiDPI OpenGL viewport масштабируется в физические пиксели, поэтому Physics занимает всю область визуализации и остаётся центрированным.

## Особенности реализации

- `src/Physics.hpp/.cpp` — чистое математическое C++-ядро без Qt, пригодное для отдельного тестирования.
- `src/GLView.hpp/.cpp` — OpenGL 3.3 Core, GLSL 330, шейдеры и камеры.
- `src/MainWindow.hpp/.cpp` — десктопный интерфейс Qt 6 Widgets.
- `tests/physics_test.cpp` — автоматические тесты простых физических условий.
- Режим `Physics` использует тот же OpenGL 3.3 / GLSL 330 путь на всех ОС и не требует OpenGL 4.3 compute shaders, CUDA или vcpkg.

### Оптимизация

- В галактическом Leapfrog ускорение с конца предыдущего подшага переиспользуется в следующем: после прогрева выполняется один, а не два расчёта потенциала на звезду и подшаг.
- Убраны дорогие `pow(x, 1.5)` из горячего цикла; используются произведение и квадратный корень.
- При наличии OpenMP расчёт независимых звёзд автоматически распараллеливается для больших массивов.
- Опорные орбиты Galactic Center один раз собираются в статический VBO, вместо пересчёта и 15 загрузок в GPU на каждый кадр.
- Потоковый VBO звёзд растёт по необходимости и затем переиспользует выделенную ёмкость.

### Честные ограничения

1. Визуализация научно мотивирована, но не претендует на точность астрономического наблюдения. Не используйте её для публикационных выводов без дополнительной валидации и сверки единиц измерения.
2. TDE реализован как событие потери точечного объекта: половина массы считается аккрецированной, гидродинамика потока и выброшенного вещества не моделируется. Прямой захват сохраняет линейный импульс; для TDE отсутствующая половина массы представляет покинувшие расчёт обломки.
3. Используется OpenGL, а не Metal. На macOS OpenGL устарел, но OpenGL 4.1 Core по-прежнему поддерживается многими актуальными системами. Для отдельной Metal-версии потребуется другой графический backend.
4. Масса в интерфейсе устанавливается в миллионах солнечных масс, масштаб BH-камеры выражен в радиусах Шварцшильда. Галактический и центрический режимы используют разные системы единиц; переключение видов намеренно изменяет масштаб сцены.
5. Астрономические каталоги Gaia пока не включены. Для работы офлайн данные не нужны.
6. Physics воспроизводит визуальную модель референса, включая суперпозицию высот сетки. Это не полная динамическая метрика нескольких тел: гравитационные волны и нелинейное решение уравнений Эйнштейна не вычисляются.
